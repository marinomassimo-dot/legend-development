# ADV-299 result (HE, 2026-11-28): who writes while free space swings, and the profile leak

PREREG: `PREREG_ADV299_HE_20261128.md` (commit eb890eef9). Trace: `disk_trace_adv299_20261128.tsv` (20 KB), run 05:20Z to 05:50Z,
sampled every 10 s with `framework/scripts/disk_writer_trace.py` (read-only; tests in `test_disk_writer_trace.py`).

## 1. The writer trace
- Free space over the 30 minutes: start 1668 MB, minimum 1520 MB, maximum 3066 MB; **12 drops of 100 MB or more**, in pairs:
  about -460 MB then about -900 MB within 30 to 60 s (05:21:09 -465, 05:21:46 -933; 05:23:49 -457, 05:24:19 -853; 05:28:21 -378,
  05:28:50 -941; 05:47:21 to 05:50:17 a run of -302, -468, -469, -466, -400, -663), each followed by a recovery of the same size.
  A sawtooth of one gate clone built and removed, not a steady fill.
- Writers at the drops, by cumulative write_bytes: the `safe_push.py development main --serialize` family (four processes of
  other actors queued and running, about 1.85 GB each: the landing gate's clean clone and the derived-surface regeneration;
  `candidate_tree_freshness.py --regenerate` 482 MB; a `git clone --no-hardlinks --no-checkout` 398 MB). The Codex app-server
  (pid 500783) wrote 390 MB over the run, about 13 MB per minute, into one 587 MB rollout `~/.codex/sessions/2026/11/21/rollout-...jsonl`:
  steady, not a swing (the `dir` rows show ~/.codex as 600 MB modified at every drop only because a rewritten file counts whole;
  the process rows give its real rate). `~/legend_browser_tmp`: 1 MB. `~/.cache`: 0.
- Two limits, stated: (a) the four safe_push processes show nearly identical totals (1850 to 1857 MB), so /proc write accounting
  cannot separate them (one holds the landing lock at a time; the others wait): read it as one family. (b) Two `claude bg-spare`
  daemon processes show 1.9 GB and 1.5 GB in a single sample with no open file; not explained, treated as unreliable.
- **Verdict: the swings are the landing gate itself.** One gate clone peaks at about 0.86 GB (measured 2026-11-24) and a push
  also regenerates derived surfaces; with 1.5 to 3 GB free, two overlapping clones or a clone beside a regeneration take the disk
  to its floor. The Codex rollout is a steady 13 MB per minute underneath. The prediction in the PREREG ranked the Codex writer
  first and the /tmp clones third: the order was wrong, the third item was right.

## 2. The leak at the source (the `~/legend_browser_tmp/tmp*` folders)
- The 247 folders each hold a Chromium profile `p` and the page `v.html`: the layout of `test_repurposing_view.py`, class
  `Browser` (and `CuratedBrowser`). Its class-level `tempfile.TemporaryDirectory()` was removed only by `tearDownClass` (not run
  when the suite is killed; raises when a browser child still writes), and `dom()` ran `subprocess.run(..., timeout=120)`, which on a
  timeout kills only the parent browser process, not its children. File and line before the fix: `framework/scripts/test_repurposing_view.py`
  setUpClass (line 285) and `dom()` (lines 295 to 299). The "directory not empty" race itself was NOT reproduced with a synthetic
  writer (the old cleanup succeeded), so the missing guarantee is for the killed-suite and timeout paths.
- Fix (commit b6c8601e5): `framework/scripts/browser_scratch.py` (`run_browser` runs the browser in its own process group, output to
  files not pipes, kills the group on exit or timeout; `remove_tree` stops any process naming the profile and removes the tree, with
  retries) and `test_browser_scratch.py` (4 tests: failing run, timed-out run, a live writer, and the class-level shape after a
  failing test: the folder is gone). `Browser.setUpClass` registers `addClassCleanup(remove_tree)`; `dom()` uses `run_browser`. One real
  `Browser` test run left no new folder (436 entries before and after). Nothing existing was deleted.
- NOT fixed, outside this scope: 24 further per-method `TemporaryDirectory()` uses in the same test file (RealViewports etc., with
  `rv.Cdp`, which cleans its own profile).

`repurposing_view.Cdp`), about 2 GB of memory: 22 are older than 66 hours (up to 221 h: before my watcher of 2026-11-25, commit 16a01c945),

(3.7 h), two `eeg-verify` browsers (38.7 h, under `files/coordination/adv-codex-loop` and `~/legend_browser_tmp`). Those callers set TMPDIR to
`legend-amiloride-*` and `eeg-verify.*`; no tracked script names these prefixes, so the launcher is outside the repository (a Codex-lane or ad hoc
runner using an older copy of `repurposing_view.py`: 10 worktrees on disk still lack `_watch_browser`). File and line cannot be given.
