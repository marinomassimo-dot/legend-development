# Addendum 1 to the scoring spec (HE, 2026-11-22), written before IT's score file was opened; sealed, digest committed.
Reason: IT's frozen method (d4ff2ce91) names two baselines and its own metric; ADV's return 16 asks for both metrics and a title. Nothing here uses any score or outcome.
1. The frozen spec's "declared baseline" is read as IT's **B1 (class prior)**, the comparator IT's method names for the engine-minus-baseline gap; **B2 (lipophilicity)** is reported as a second, descriptive comparator on the primary rows only. IT's score file columns: id, engine_score, baseline_b1, baseline_b2, recognised.
2. The ORIGINAL metric of d4ff2ce91 is computed too and labelled 'original': AUC of the engine score against the label on the primary rows with the same stratified alias-group bootstrap (10,000 draws, seed 175, percentile interval), a label-permutation p (groups permuted among eligible groups, positive count kept, 10,000, seed 175, one-sided), and the engine-minus-B1 gap. The ADDENDUM metric (with its 0.10 margin) is IT's text written after its scores and before outcomes; I compute it from that text as written, scores unchanged, and label it 'addendum'.
3. Title of the aggregate summary: "LLM generic-perturbation rubric against class prior" (the rubric orders acute, direction-agnostic plausibility; the outcome is chronic normalisation). First two lines: (1) LEGEND engine evaluation on CDKL5 = CLOSED, NOT FEASIBLE (no target-agnostic reusable procedure); (2) the diagnostic result: point estimate, counts of rows, groups and positives, paired interval, scope = the defined subset.
4. IT's `recognised` column is read for the recognition stratum and for a note on any row it flags; the scores are not adjusted.
5. Script v2 `score_adv175.py` implements 1 and 2 (the v1 frozen script is kept as `score_adv175_v1_frozen.py`; on the dry runs the shared primary and sensitivity numbers are identical).
