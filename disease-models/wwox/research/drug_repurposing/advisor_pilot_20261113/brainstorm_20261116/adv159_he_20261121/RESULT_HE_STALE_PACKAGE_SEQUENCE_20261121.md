## 5. EMPATHY and DREAM
- **Lesson (correction log, with its boundary):** the command people run and the CI assertion should test the same condition at the same point. Here they do (same function). The quick commands that look similar (`check`, `i18n`) test other conditions, so a green pair is not a green package. Boundary: this holds for the shareable package; other generated artefacts (questions file, receipts) have their own check.
- **DREAM (earlier receipt-count regeneration issue, the i18n exit, the stale package after regeneration):** all three are a generated artefact left stale after an upstream edit, found by a check other than the one a quick pass runs. For the earlier receipt-count regeneration issue I rely on the repository's own note (regenerate the dossiers and run the touched folders' tests before freezing), which I did not reopen here; the i18n one was closed by an exit code; the third needs no change because the command already exists and is named in the README row. **A single "what is stale" wrapper is the obvious connection and is weak:** three artefacts with three different cost profiles (7 s, 100 s, minutes) and no occurrence where a wrapper would have saved a failure the row did not.
