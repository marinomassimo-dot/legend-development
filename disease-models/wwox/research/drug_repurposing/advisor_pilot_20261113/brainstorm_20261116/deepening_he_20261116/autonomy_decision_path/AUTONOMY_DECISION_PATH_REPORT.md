## 2 · Three things kept apart, and where each loses the rule
| layer | what it said | what was wrong |
|---|---|---|
| **tick result** (mechanical) | `verdict: NONE`, `queue.exhausted: true` | `exhausted` is computed from task records only (`queue_state`: no record with verdict CONTINUE). It is a statement about written tasks, not about the portfolio, but it was printed as "the executable queue is exhausted" with no scope and no blocked paths. The tick output did carry `portfolio.actionable` (8 ready rows) and nothing used it. |
| **hold** (host decision) | a general wait until a specific intake record changes | `hold()` required a reason and a resume condition and nothing else: no paths left out, no check against the portfolio, and the hold had no end except its resume record, a roadmap change or the first new event. A specific blocked intake stood for the whole portfolio. |
| **presidio decision** (what the presidio reads and answers) | "HELD by host … the executable queue exhausted" / "WAITING (legitimate)" | the line repeated the hold's claim as a state of the portfolio. A stated wait from an evaluation had the same property: it needed `excluded` and `reason` in prose, and any prose passed. |
The canonical text was already right ("A closed mandate, an empty queue or no new radar does not end the work", HE57; "a whole-portfolio wait remains valid for a supported resource limit, a reserved act without an alternative, or an actual absence of useful reachable work"; the recall text said "these mechanical verdicts do not establish that all useful work is exhausted"). **The rule was lost in the implementation and in the wording a tick prints**, not in the instructions. A `NONE` outcome or a blocked specific intake does not show that scientific opportunities are exhausted.

## 3 · What changed (all in existing files)
`framework/scripts/strategic_advisor.py` and `test_strategic_advisor.py`:
1. `tick`: `queue` carries `scope` ("written executable tasks only; not a statement about the portfolio"), `blocked_paths` (the waits the tick already computed: task, step, blocker) and `portfolio_ready`; `exhausted` is kept for compatibility. The presidio line says "no written executable step … the closing comparison of section 12 is the next step".
2. `hold`: requires `--excluded` (the paths left out, record ids, portfolio rows or files, each with its cause; prose without a path is refused), is refused while ready portfolio rows are named neither in `--reason` nor in `--excluded`, stores `excluded` in `holds.jsonl`, shows it in the HELD line, and **lapses at `min_hours_between`**: the tick then says EVALUATE "hold lapsed: re-compare".
3. A stated wait from an evaluation must name every ready portfolio row it leaves out with the cause, otherwise it is read as unstated; a wait saved before this rule that does not name them triggers ONE evaluation per portfolio state (not one per hour).
4. `recall_prompt`: the clause "a blocked path is not a blocked portfolio; an EVALUATE left unrun needs its excluded paths and a resume condition", and an eight-hex `[text …]` tag after the mark (see 4a).
5. The evaluation's run folder is assembled in the state directory and moved into the campaign folder in one step (see 4b). Preserved: operator pause (verdict PAUSED), resource limits, reserved acts, real waits (a wait that names its rows stays valid until its condition), and the existing one-evaluation-per-situation discipline.
Other places: `framework/scripts/safe_push.py` (earlier landing, `--serialize`); `framework/scripts/judge_input_check.py` (new, routed once; see 4e); `scripts/legend_commit.sh` + `scripts/test_structured_data_integrity.py` (4d); `framework/scripts/hypothesis_package.py` (4c); `framework/scripts/README.md` rows; one line in `CLAUDE.md` §3.

## 6 · Limits that remain
* The P16-era quiet ticks (12:00 to 20:35Z) could not be replayed (state overwritten); the rule changes cannot be shown to cover that stretch, only the overnight hold and the closing wording.
* "Ready" is the portfolio's own status: a row marked ready that is not truly reachable would still force a naming; the remedy is to mark it `waiting` with a `resume_when` (a row edit), not to word around it.
* Naming a row satisfies the check; whether the cause given is true is a judgement of the presidio (the check cannot read it).
* The tracked ledger append during an evaluation (4b); the installed recall exists only in the ADV session's memory (CronList, session-only), so its tag must be compared by a session; there is no host-side check of it.
* The closing question of a meeting is text written by the presidio; the rule is in the canonical §12 and §13 (ADV's change), not enforced in code.

## 7 · Removal path
Each change is one commit and independent: `git revert` the commit for the area (strategic_advisor + its tests; `legend_commit.sh` structure check + `LEGEND_STRUCT_PATHS`; `judge_input_check.py` + README row; `hypothesis_package.py` NEXT line; CLAUDE.md line). A `hold` that must stay general can be recorded with `LEGEND_STRUCTURE_BECAUSE`-style stated exception only for structure; for holds there is no override by design: name the paths or mark the portfolio rows `waiting`. Nothing else holds state: no file, service or cron was added.
