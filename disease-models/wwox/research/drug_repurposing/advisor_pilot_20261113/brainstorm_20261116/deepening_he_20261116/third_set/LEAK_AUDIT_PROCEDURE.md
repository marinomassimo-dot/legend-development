# Question-leak audit (registered at the freeze of every target; ADV's standing line, 2026-11-17)

Purpose: T6 showed that a question whose own wording carries the atom or its class measures the question, not the engine. Before any run, for each target:
1. Write the atom class in one phrase (the lever CLASS, no agent).
2. Check the question text, and the output-field wording, for that class or a direct synonym of it: list every phrase of the question that names or entails a lever class. Entailing counts: "tolerate nuclease-induced breaks" entails a repair lever.
3. Rewrite until the question names only the DEFECT (what is broken, in physical-chemical terms) and the OUTCOMES to predict, never a mechanism family. A question may say "restore function" but not "repair", "supply", "stabilise", "chaperone", "cofactor", "ion", "metabolite".
4. A second reader (a delegate with no file tools and no atom) is shown the question only and asked to list the lever classes the question suggests; if any equals the atom class, the question leaks and is rewritten; the audit result and the rewritten question are frozen with their hashes.
5. The result of the audit is written beside the target in the freeze; a target whose class cannot be separated from its defect (the defect IS the class) is dropped.
6. Template-named class (ADV A1): record yes or no whether the atom class is named in the axis list of the v4 template; if yes, lever-class credit is void for the v4-versus-v3 decision and only STRICT credit decides.
