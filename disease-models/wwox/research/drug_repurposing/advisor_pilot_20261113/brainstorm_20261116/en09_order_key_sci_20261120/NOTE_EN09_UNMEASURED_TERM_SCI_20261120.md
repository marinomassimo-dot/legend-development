# EN-09: does the UNMEASURED_AT_MAIN_TARGET term of the hand-over order key move any hand-over? (SCI successor, 2026-11-20; ADV-approved, one sitting, zero spend; computed on the held generation results; hypothesis level; not medical advice)

**Answer first.** Removing the term (k3 of `order_key` in `generation_it21_p2_20261103/run_generation_it21.py`) changes the generator's hand-over by **one cluster of 15**: Q5 / H_HARM / PTPRB (razuprotafib) leaves and Q5 / H_HARM / TEK enters, represented by foretinib instead of altiratinib; and it changes **2 of 44** cluster representatives in all. **Neither moved compound is named in any card, agent sheet or pilot arm** (text search of the repository outside the generator, identity and qualification tables), so the order is a presentation for the current consumers and not a decision input; the one boundary case is recorded for IT as a possible rule item, not a defect.

**Method (reproducible).** Input: the newest saved proposals table, `generation_it41_20261109/results_s18/proposals_it21.tsv` (994 proposals, 220 `handoff_eligible`). The key and `select_handoff` were re-implemented as in the source (six terms: cluster work done, seed support limited, UNMEASURED_AT_MAIN_TARGET, minus origins, chain edges, minus zmin; best row per (question, hypothesis, main target); at most three clusters per (question, hypothesis)). **Control:** with the key as is, the re-implementation reproduces the saved `handoff_it21.tsv` exactly (15 proposal ids). Variant: the same with k3 set to 0. A different date of the generator (later runs did not save a proposals table) could differ; the table read is the newest held.

**Numbers.** Of 220 eligible rows, 16 are UNMEASURED_AT_MAIN_TARGET (65 NOT_ASSESSABLE, 57 SINGLE_MEASURED_TARGET, 55 ATTRIBUTABLE, 12 NOT_COMPARABLE, 9 SECONDARY_ACTIVITY, 6 BORDERLINE). Of 44 clusters, 5 hold both an unmeasured and a measured eligible row. **No UNMEASURED row is handed over with the key as is.** Without k3 the handed-over set differs by one cluster:
| Cluster | As is | Without k3 |
|---|---|---|
| Q5 / H_HARM / TEK | representative altiratinib (ATTRIBUTABLE, 1 origin); not handed over | representative foretinib (UNMEASURED, 2 origins); handed over |
| Q5 / H_HARM / PTPRB | razuprotafib (2 origins, chain 3, SINGLE_MEASURED_TARGET); handed over | not handed over (the cap of three per group) |
| Q5 / H_HARM / NR1I2 | phenobarbital (NOT_ASSESSABLE, 1 origin) | lovastatin (UNMEASURED, 1 origin); neither handed over |

**Reading.** (1) The roadmap's worry (a compound measured elsewhere ranks after one never measured, so knowing more is not rewarded) is real in one row, NR1I2, where an assessed-nowhere compound beats one measured elsewhere; it changes no hand-over. (2) In TEK the term works as the engine says it should (the listed target may not be the main action of foretinib, which has no measured value there); removing it would hand over a compound whose attribution to the listed target is the unknown, on two origins against one. (3) The one-cluster move is at the cap boundary of one group and involves compounds with no downstream consumer, so **the order is a presentation**; if IT wants the penalty softened, the smallest change is to rank UNMEASURED_AT_MAIN_TARGET rows ahead of NOT_ASSESSABLE ones and still behind measured ones (not tested here; one more variant for IT's rule list, not a recommendation).
