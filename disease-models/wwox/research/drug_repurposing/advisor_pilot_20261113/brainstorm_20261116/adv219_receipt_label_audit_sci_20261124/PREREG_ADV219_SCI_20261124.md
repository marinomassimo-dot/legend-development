## 2. Two different things, kept apart (frozen definitions)
* **Class A, MISLABEL:** the latest receipt labels a section `not_present` (absent) or `unavailable` and the held artefact contains it. The label contradicts the bytes. Headline number 1 = share of partial records with at least one class A flag.
* **Class B, OWED BUT HELD:** the latest receipt labels a section `not_read` or `captions_only` (honest about what was read) and the held artefact contains the section. The label is true; the content is in hand, so closing the debt costs reading, not acquisition. Headline number 2 = share of partial records with at least one class B flag.
* A section the latest receipt marks `read`, or `unknown_legacy`, is never flagged (unknown_legacy count is reported).

## 3. Population and matching
* Studies are keyed as the ledger keys them: `study_id.pmid`, else `study_id.doi`, else the id token in the event id (preprint ids). The latest receipt per study is the one with the greatest `event_at` among `contemporaneous_receipt` events (ties: highest event id). A sensitivity count uses the best state across all receipts of the study (the `owed_sections.py` semantics) and is reported beside the primary one.
* Primary population: studies whose latest receipt depth is `partial_fulltext_read`. Secondary population (reported separately): latest depth `queried_not_full_read` or `abstract_only`.
* Held artefact search, read only: `files/fulltext` and `files/deepening_downloads` of the root checkout (extensions xml, pdf, html, htm, txt). Match rule, in this order: (1) the file name contains the PMID digits preceded by "PMID" or the preprint id token; (2) the file name contains the DOI with "/" replaced by "_" or "-"; (3) the receipt `source_locator` basename equals the file name. Several files: all are scanned and a section counts as contained if ANY matched artefact contains it. No match: the study is listed as `no held artefact` and is outside both denominators (reported as a count). No fuzzy title matching, no hashing-based matching (the receipt `source_fingerprint` is compared to the matched file digest only to annotate, never to include or exclude).

## 4. "Demonstrably contains" rules (a flag needs the evidence string recorded)
* **XML (JATS):** abstract = an `abstract` element with text; introduction, methods, results, discussion, limitations = a `sec` whose title matches (case-insensitive: intro*, method*|materials and methods, result*, discussion, limitation*); tables = a `table-wrap` with at least one `tr`; references = a non-empty `ref-list`; figures = a `fig` element WITH a graphic file of that name present in the same folder (otherwise captions only, not flagged); supplementary = a supplementary file of the same study held by name (rule 5), never the mere link.
* **PDF and plain text (pdftotext, per page):** headings = a line (after whitespace trim) equal to the section word (Abstract, Introduction, Methods, Materials and Methods, Results, Discussion, Limitations, References), optionally numbered; tables = a line that starts with "Table N" followed by "." or ":" and the page carrying at least three further lines with two or more numeric tokens each; figures = a line that starts with "Figure N" or "Fig. N" followed by "." or ":" on a page that has at least one embedded image or fewer than 1500 characters of text; supplementary = a line that starts with "Supplementary Figure N", "Supplementary Table N", "Supplemental Figure N" or "Extended Data Figure N" ON A PAGE AFTER the page where the References heading first occurs, or a separate held file whose name matches supp|suppl|mmc|media|additional|NIHMS-supplement for the same study.
* **HTML:** a heading element (h1 to h4) whose text matches as for XML sections; tables = a `table` element with at least two `tr`.
* A prose mention ("see Table 2", "Supplementary Figure 3 shows") is never evidence. Extraction failure (no text layer) is recorded as `not_assessable`, never as a flag.

## 5. Precision check (frozen)
* Flag universe = every class A and class B flag. Seed 20261124, `random.Random(seed)`; the flag list is sorted by (study key, section) before sampling; sample 15 flags: up to 8 from class A and the rest from class B (all class A if fewer than 8).
* Hand check by opening the artefact at the recorded location and answering: (i) does the named section exist in the artefact as a real section (not a mention), yes or no; (ii) for class A, is the receipt label contradicted, yes or no. Precision = verified yes of 15 on question (i); the class A subset is reported separately. If precision on question (i) is below 0.8 the flag rules are reported as failing and the headline numbers are given as upper bounds only, with the failure patterns listed; the rules are NOT changed after the sample is drawn (a revised rule would be a second pre-registered run).

## 6. The ten records where completing the read could most plausibly change an OPEN row
* Candidate set: flagged records (class A or B) in the primary population.
* Score (fixed): +3 for each OPEN, IN_PROGRESS or CLAIMED row of `open_questions_map.tsv` whose text, source reference or status evidence contains the record's PMID, DOI, preprint id or "PAPER <n>"; +1 for each such row sharing at least two rare title tokens with the record (a token of 6 or more letters that is not among the 60 most frequent title tokens of all registry records); +2 if any flagged section is a data-bearing one (results, figures, tables, supplementary). Ties are broken by lower PAPER number. The ten are the top ten by score after a manual check that the linked row and the record are about the same question (a rejected link is replaced by the next in order and the rejection is listed). RP-003 context: OPEN rows only; no CLOSED or CONCLUDED row counts.
* The result states, for each of the ten, the section to read, the row, and the decision it could move, as hypotheses.
