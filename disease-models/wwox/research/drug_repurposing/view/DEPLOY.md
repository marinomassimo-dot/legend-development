# Deploying the shareable view (proposal, nothing is activated)

Status, 2026-10-29. This document prepares the Internet deployment of the redistributable package
`view/shareable_package/`. **Nothing has been published, enabled or changed outside the repository.** No account was
created, no spend was incurred, no contact was made. The only decision this document leaves open is listed in section 9.

## 1. What is deployed

The directory `disease-models/wwox/research/drug_repurposing/view/shareable_package/` and nothing else. It is a static site: `index.html`
is one self-contained file (inline CSS and JavaScript, data embedded as JSON, no network resource), next to `NOTICE.md`, `COMPARISON.md`,
`README.md`, `manifest.json`, `TEXT_PROVENANCE.json`, `LICENSES/` and `class_b/chembl_cc-by-sa-3.0/` (the ChEMBL records as a separate
CC BY-SA 3.0 file with its own licence text and credit). The page is Italian for the physician and is research material, not medical advice,
not a ranking of treatments and not a probability of benefit. It carries no individual-level record.

## 2. Proposed destinations (all reachable from the Internet without creating an account or spending)

| | Destination | Why it fits | Limit |
|---|---|---|---|
| A (proposed) | GitHub Pages of the existing repository, served from the package directory by a manual workflow | Uses the account and repository that already exist; free for a public repository; the artefact is exactly the package directory | Pages is available only if the repository is public (or on a paid plan). **Whether the repository is public today is not verifiable from inside the repository** (`licence_inventory_it7_20261029.md`, section 9): confirm it before relying on this route |
| B (fallback, no hosting) | The deterministic zip of the package attached to a GitHub Release of the same repository | A recipient downloads the zip and opens `index.html` from `file://`; the NOTICE and licence texts travel with it | Needs the same repository and a release object; it is a download, not a web page |

Not proposed: any static host that needs a new account, a payment method or a verification of identity.

## 3. The workflow, kept as a proposal

`view/DEPLOY_pages_workflow.proposal.yml` is the whole mechanism. It has one trigger (`workflow_dispatch`), so it cannot run on a push, a
schedule or a pull request. Its first job (read-only permissions) checks that every file in the package directory, `manifest.json` included, equals the digest in the table of section 4 and in the manifest, and that no
other file is there; this is an integrity check, not a content check (the content proof is `audit-shareable --dynamic`, section 7). Its second job, the only one with `pages: write` and `id-token: write`, publishes that directory with the official Pages actions. The Pages environment normally accepts deployments only from the default branch: dispatch the workflow from that branch, after the work has landed there. It is **not** under `.github/` and is not
active; nothing was added under `.github/` by this work. Every `uses:` is pinned to a commit SHA (section 11); re-check them before activation.

## 5. Reproducible build and check

From the repository root, with `LEGEND_CATALOG_CACHE` pointing at the catalogue cache (it is not tracked; the counts of the page do
not depend on it but the package build reads the catalogue):

```bash
python3 -B framework/scripts/repurposing_coverage.py run                      # only if the inputs changed
python3 -B framework/scripts/repurposing_view.py run --source shareable
python3 -B framework/scripts/repurposing_view.py package                      # writes the package and the table of section 4
python3 -B framework/scripts/repurposing_view.py package --check              # exit 1 if the folder or the table differs from a fresh build
python3 -B framework/scripts/repurposing_view.py package --zip PATH           # deterministic zip (fixed timestamps, sorted entries)
python3 -B framework/scripts/repurposing_view.py audit-shareable --dynamic    # the publication proof, must PASS
python3 -B scripts/public_release_gate.py                                     # the repository gate
```

1. `audit-shareable --dynamic` passes for `index_shareable.html` and for the package: no value traceable to a non-allowlisted source, in the
   bytes, the rendered pages, the exports, the printable sections or the PDF text. At the time of writing it passes with 0 violations.
2. `package --check` is current, so the files and the table of section 4 are those a fresh build produces.
3. `NOTICE.md` and `LICENSES/` are present in the package (the proposal's verify job requires them).
4. No class-C content: the page carries counts and identifiers for third-party rows whose terms are unread or non-commercial, never their text.
5. No individual-level data and no private communication: the page describes a WWOX-DEE genotype class only.
6. `scripts/public_release_gate.py` passes on the commit.
7. **The repository-history findings are an open, reserved decision.** `licence_inventory_it7_20261029.md` reports, among others, history-only
   blobs that the release gate would block, class B and C catalogue rows in every version since the first commit, and seven page crops of a
   copyrighted paper that exist only in history. **Publishing the package does not change what the history already holds, and it does not
   remedy any of it.** It also does not depend on resolving them, but the person who decides should know that the deployed site points to the
   same repository.

### Search engines (a decision to take before publication)

The page carries no robots meta tag, and a public Pages site is indexable. Two options: accept indexing explicitly, or add
`<meta name="robots" content="noindex,nofollow">` to the page template in `framework/scripts/repurposing_view.py` and regenerate (a one-line change that
also changes `index.html` and its hash). This is proposed, not done: it changes what is published and belongs with the decision of section 9.

## 8. Rollback

1. Stop serving: repository Settings, Pages, "Unpublish site" or disable the Pages source (the label of the control depends on the Pages source type and could not be checked offline), or delete the `github-pages` environment deployment. Effective within minutes;
   CDN caches may serve the page for a short time. Actions artefacts and the deployment history stay until deleted.
2. Remove the mechanism: delete `.github/workflows/<copy of the proposal>` in a commit (or `git revert` the commit that added it). The
   proposal file under `view/` can stay; it does nothing there.
3. For route B: delete the release asset and, if wished, the release.
4. Revert any generator wording change of section 6 with `git revert` and regenerate.
5. What a rollback cannot do: recall copies a third party already made, or edit history. Those belong to the reserved decision below.

## 11. Service settings, pinned versions, the exact workflow diff, URL, updates, indexing, retirement (iteration 8, verified 2026-10-29)

**Facts from the official GitHub documentation** (docs.github.com, read on 2026-10-29; each is the page's own statement):

* Publishing source: repository Settings -> Pages -> "Build and deployment" -> Source -> "GitHub Actions"; the flow is check out, upload the artifact with `actions/upload-pages-artifact`, deploy with `actions/deploy-pages`; the deploy step is skipped on a pull request.
* The workflow templates use the deployment environment `github-pages`; GitHub "recommend[s] that you add a deployment protection rule so that only the default branch can deploy to this environment".
* `actions/deploy-pages` (README, v5.0.1): the deploying job needs at least `pages: write` and `id-token: write` and should target the `github-pages` environment; `actions/upload-pages-artifact` (v5.0.0): `path` (default `_site/`), `retention-days` (default 1), `include-hidden-files` (default false; `.git` and `.github` are always excluded).
* Limits: published sites no larger than 1 GB; source repositories recommended at most 1 GB; soft bandwidth limit 100 GB per month; deployments time out after 10 minutes. Pages "shouldn't be used for sensitive transactions like sending passwords or credit card numbers" (the page is static and collects nothing).
* Project-site URL form: `http(s)://<owner>.github.io/<repositoryname>`.
* Not stated on the pages read, so NOT asserted here: which plans can publish from a private repository; whether a site from a private repository is publicly reachable; how long cached copies persist after unpublishing. Check the Pages section of the repository settings before activation.
