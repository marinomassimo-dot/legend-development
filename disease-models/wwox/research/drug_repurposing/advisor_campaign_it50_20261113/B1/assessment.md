## Response to the intended action

**Verdict.** The intended action is a sound choice and better than my Stage A on one count: it targets a limit the campaign has already exposed (INV-02 returning 0 rows for the node the card cares about), and it comes with a before/after run of the generator, which gives it a measurable output. My Stage A item was depth in an existing thread. This one is a representation fix with a check built in. I do not argue for replacing it. I would change four things.

1. **Keep "representable" separate from "supported".** Making the eIF2B activator representable must not move any rank, sign or qualification. The ISR protein-level sign is the premise that blocks any compound. The package should therefore list that sign as a precondition, and the comparison against PERK inhibition and the genetic arm should be conditional on it. The result I would count is that the generator's before/after output differs only in a new, labelled "name-reached probe" row. Every existing rank and sign must come out byte-identical. If any other row changes, the package has done more than represent the lost proposal.

2. **Two things the package must not do.** First, it must not add a reader. Harness owns the minimal link for design-only packages (OBJ_P4), so the package should supply the artefact and a second real case and stop there. Second, it must not claim that the genetic arm (loss of the eIF2α phosphatase regulatory subunit) is feasible. Its place is the discriminating-result slot only.

3. **Make the representation reusable.** The same limit shows up in my Stage A finding. The computed Kir-subunit join exists in `cell_context_it46.tsv` and no consumer carries it. I would write the new fields (qualification gaps, conditional comparator, discriminating result) generically enough that one INV-18 row can be expressed in them as a second test case. If the shape fits both INV-02 and the Kir2 arm, it is a representation. If it fits only one, it is a one-off.

4. **Fold in the cheap items.** These are zero-spend regenerations and fit the same pass: apply `kir2_drugname_sci49_20261112/consumer_delta.md` row 1 (verified, still PROPOSED), and regenerate `needs/needs.md`. That table says 22 needs while `needs.json` holds 24, and the two missing ones include `NEED-INTRINSIC-EXCITABILITY`. A before/after generator run makes this a natural place to do both.

**Where my Stage A view still stands.** The Kir2 cell-class propagation is not displaced. It is a smaller, separate delegate item. Under the one-delegate-at-a-time constraint, it should come after the INV-02 package, or be dropped if SCI50 delivers a Kir2-composition reading first. It also does not need a delegate if the INV-18 owner can apply the Kir2 gene-state values directly. I flagged that those values are already committed.
