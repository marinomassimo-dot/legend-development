## Answer first
1. **Service state, observed (not inferred):** the ChEMBL public REST `status.json` answered **UP, ChEMBL_37, at 2026-11-13T21:24:31Z (before) and 21:25:21Z (after)**; the script made 62 requests, all HTTP 200, plus the two status rows (`service_state.tsv`). The route works today.
2. **The by-target activity route returns rows, for the 12 targets queried (denominator: 12 gene symbols, resolved by UniProt accession to 12 human single-protein ChEMBL target records; none unmapped):** eIF2B subunits alpha to epsilon (EIF2B1–5): **2, 2, 12, 4 and 8 activity rows (28 in total)**; the eIF2 alpha kinases EIF2AK1–4: 744, 785, 924, 2,208 rows; EIF2S1 148; PPP1R15A and PPP1R15B 1 each; 4,839 rows pulled in all (`activity_counts.tsv`, `activity_rows.tsv`).
3. **None of the 28 eIF2B-subunit rows is an eIF2B activator.** They are off-target or proteomic binding rows: Kinobead pull-down Kd/ED50 values for two compounds (CHEMBL5653589 on EIF2B1–4, CHEMBL3752910 on EIF2B3–5), mass-spectrometry pull-down "Activity" rows (CHEMBL4129274, two cell lines), and molibresib (CHEMBL1232461) fold-change and IC50 rows on EIF2B3 and EIF2B5 in one coomassie-staining proteomic document. **So the statement "0 rows for raising eIF2B activity" is a true absence at this scope** (five eIF2B subunit targets, ChEMBL_37, 2026-11-13), now reproduced under a responding service, not an artefact of the outage.
4. **Where the earlier "0 rows" came from, and what it did and did not say.** In IT49 (`generation_it49_20261112/p5_case_inv02/result_it49.md`) the "simple target search" was `action_search.py` on **GtoPdb interactions and ChEMBL's curated mechanism table**: 12 rows over the 12 targets, 0 for raising eIF2B activity. This probe confirms the curated side: **the ChEMBL curated mechanism table has 0 rows for each of the 12 targets** (`mechanism_rows.tsv` is empty). The IT50 table's "0 rows by target search" therefore refers to that curated route; **the activity-endpoint route was never run** (IT50 stated it was blocked by an HTTP 500 and did not run it): the blocker was real on that day and has lifted.
5. **Identifier mapping is a second effect, separate from the outage.** The best-known eIF2B activator, ISRIB, is in ChEMBL (CHEMBL4303573) with **9 activity rows, none filed under an eIF2B target** (SARS-CoV-2 ×3, HDAC6 ×2, "no relevant target" ×2, replicase polyprotein ×1, ATF4 ×1): a by-target query on the eIF2B subunits cannot see it; a by-molecule query can. The clinical eIF2B activator fosigotifator (CHEMBL5315045) is a molecule record with **0 activity rows**; the name searches for 2BAct and sephin1 returned no molecule record (a name-search result only, not an absence in the resource under other names). Salubrinal, guanabenz, GSK2606414 and GSK2656157 have molecule records.
6. **Shipped tool not run.** `generation_it44_20261110/activity_search.py` reads the same public activity endpoint but resolves gene symbols through a cached ChEMBL target file (`catalog/cache/chembl_activity/<release>/chembl/targets.jsonl.gz`) that this checkout does not hold; its "no cached release" is a **cache dependency**, in addition to the outage. My queries used the UniProt-accession lookup and the same endpoint.
