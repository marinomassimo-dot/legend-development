## DECISIONS_TAKEN

🔴 **ALL FOURTEEN ARE STALE TOTALS. THE MIS-MEASUREMENT CLASS IS EMPTY, AND THE TOOL'S `D-40` LABEL IS A FALSE POSITIVE ON BOTH ROWS IT FIRED ON.** The brief named `PAPER 004` (PMID 33914858) and `PAPER 156` (PMID 35460704) as carrying the D-40 signature, each asserting exactly **6** against a 6-key `verbatim_locators` mapping, and asked for a different repair for them — the measured count plus a note that the superseded figure was the schema key count and never a reading total. **That repair would have been false, and it was not made.** `git log` on each manifest is decisive: both held exactly **6 `entries`** at commit `28faaf0a` (2026-10-03), and both registry sentences were written the same day in `59fba0bc`. Both figures were therefore **derived correctly from the entry list and merely went stale**, exactly like the other twelve. The signature is a heuristic over a coincidence — `len(entries)` is free to equal the key count, and with a 6-key mapping it will keep doing so — so it is a prompt to re-derive, never a finding.

🔵 **Why this mattered enough to check rather than accept.** Writing D-40's note into these two records would have produced the mirror image of D-40 itself: a correction asserting that a true sentence had never been true, published in a canonical file, citing a detection rule as its authority. `BATCH_20261019_009` was caught only because the Orchestrator re-measured a number offered as a finding; this batch was handed a *label* offered as a finding and re-measured that. The repair notes on both records say the signature fired, say it was a false positive, and show the evidence, so the next reader meets the correction rather than repeating the check. The tool's own constant note and the routing row in `framework/scripts/README.md` now carry the same correction, because a tool that mislabels a class should say so where its users read it.

🔴 **`BASELINE_UNPARSED` was NOT lowered, and the five were examined one by one rather than left by default.** Three are 2026-08 Italian records (lines 6856, 6880, 6905) whose sentence asserts a count while naming no manifest anywhere in the clause — there is no link to check, so there is nothing to repair; inventing the attribution is the one thing the parser refuses to do on its own and the integrator should not do by hand. Two are line 7333, where the paper's own 38 locators are discussed **beside an erratum's manifest**: writing a figure next to that path would assert precisely the link this tool exists to verify, and the figure's own agreement with the paper's manifest cannot be stated through a sentence that names the erratum's. These are the honest-repair exclusions the brief reserved, they stay in the baseline, and the reason is now written beside the constant rather than only in this report.

🔵 **Why lowering `BASELINE_DISAGREEMENTS` to zero is the right tightening and what it costs.** The enrolled suite asserts `measured <= baseline`, so the battery would have stayed green at 14; leaving it there would have been the quiet option and would have left a ceiling with fourteen slots of headroom for a defect that no longer exists. At 0, the **next** count assertion that drifts past its manifest is loud at the next run instead of hiding under a historical allowance. The cost is real and is accepted: the registries' counts are measurements of files that keep growing, so a reading that adds locators and does not update the sentence citing them will now turn this ratchet red — which is the correct place for that noise, because the repair is cheap and the alternative is the decay this tool was built to measure.

🔵 **One test was changed, and it is worth being explicit that this is not a baseline being routed around.** `test_headroom_prints_the_instruction_to_lower_the_ceiling` failed on the lowering. Its assertion was about the tool's self-tightening message, but it drew the ceiling from the live constant, so it could only pass while the constant was above zero: a test of the tightening mechanism that fails when the mechanism is used. It now passes `--max-disagreements 3` explicitly, and the enrolled ratchet assertion `counts["disagrees"] <= BASELINE_DISAGREEMENTS` — the one that actually guards the registry — was **not** touched and now holds at `0 <= 0`.
