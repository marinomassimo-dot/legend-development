## Process diagnosis

**What the process caught, on my own work.** `test_fulltext_trace_contract.py` failed because
`FTR-20260806-19936220-01` named `staging/commit_candidate_20260806_19936220.md` among its
outputs. `staging/` is gitignored: in a fresh clone that output resolves to nothing, and the
first command in the README would return BLOCK. The test's own docstring records that this
exact failure once shipped four broken receipts. I had copied the path from the *manifest
landing list*, which is permitted to name pre-commit drafts, into the *receipt outputs*, which
is not. The ledger is append-only, so the repair was the designed one: append
`FTR-20260806-19936220-02` with `prior_receipt` set, superseding the first rather than
rewriting it. The error stays visible, which is the point.

**Three further self-caused reds, all fixed.** `test_coverage_report.py` and
`test_batch_queue.py` drifted because appending a receipt changes derived artifacts; both were
regenerated by their own documented commands. That leaves the three declared reds untouched.

**Mutation testing, before trusting the green.** A manifest that validates proves nothing until
the validator is shown able to fail. Eight mutations were run against an in-memory copy —
one word changed in a quote, `in rats` rewritten to `in mice`, a falsified SHA-256, an
abstract-only sentence claimed as body, an undeclared artifact, an ellipsis-stitched quote, a
figure locator pointed at a missing image, and one digit changed (43% → 34%). **8/8 caught.**
The abstract/body mutation matters most here: it proves the surface separation actually works
on *this* artifact, which is what makes "23 non-abstract locators" a measurement rather than
an assertion.

**What the process did not have.** Nothing in the toolchain detects a *misattributed* premise.
The unread-premise ratchet asks whether a citation was read; it cannot ask whether the source
says what it is credited with. This paper would have cleared every existing check on the day
its premise was imported, because it was readable and, once read, "resolved". That gap is the
capability upgrade below.

## Capability growth

Two gates added to `learned_gates_registry.md`:

- **`IMPORTED_PREMISE_ATTRIBUTION_GATE`** — when reading a source other surfaces already cite
  *as the origin of a premise*, run the **inbound** audit and mark each premise
  `CONFIRMED_FIRST_HAND`, `ABSENT` or `PASSED_THROUGH`. A passed-through premise must be
  re-attributed to the terminal source. Earned directly: the co-cited premise in the same
  sentence *was* first-hand, which is precisely why the sentence read as verified.
- **`SEALED_CONSUMER_CIRCULARITY_GATE`** — when a verifier is a sealed input of the baseline
  it verifies, both available repairs falsify something. Escalate as a scientific-lifecycle
  decision and let the regression stay red; a red test stating a true unresolved question is
  not a broken build and must not be silenced.
