## 1. Session handoff: the follow-up reached the wrong session and nobody checked

**Defect observed.** SCI checkpoint L, 2026-11-20: successor bound at 03:37:10Z with a text-only message (which ends the turn) and made its first tool call at 04:18:35Z, **41.4 minutes** later, because the "proceed" message went to the predecessor's row.

**Cause found, three layers.** (a) The launcher addressed a row by a reference read before the launch; the listing shows successor and predecessor under one name, and the reference is NOT derivable from the session id (probe: reference 90ee47 for session 1ac4ca4b; a bare session id and `name [ref-prefix]` are both refused as addresses). (b) A text-only bind ends the turn, so the successor waits for a message. (c) The Stop hook that would refuse a text-only end of turn is not installed: `.claude/settings.json` is `{}` and the hook's event log has no BLOCK or ALLOW event since 2026-11-18; installing it is the operator's act.

**Change.** `mandate_watch.py handoff --task <ID> --old <old full id> --new <successor id or unique prefix> [--within 5] [--wait N]` (a read of two transcripts; it starts, stops and sends nothing) answers RUNNING, STALLED, WAITING_FOR_RELEASE, WAITING_FOR_BIND, BOUND_WAITING_FIRST_ACTION, BOTH_BOUND or NEW_NOT_FOUND, and prints the delay between the bind and the first tool call. When it says STALLED it describes the row to address by name and start age. The launch brief now tells the successor to write the bind line as a text block of its own and make its first tool call in the SAME response, never ending a turn on the proof of reading or on the bind. README section 13 carries the rule and the evidence.

**Proof run.** (1) Tests: 3 new in `test_mandate_watch.py` (64 in all, OK): each step has its own verdict; a text-only bind is STALLED after the allowed minutes and a bind followed by a tool call of the same response is RUNNING; a tool call before the bind does not count; the stalled answer names the row by age when two sessions share a name. (2) Read on checkpoint L it returns the 41.4 minutes above. (3) A scratch session (sonnet, low effort, removed afterwards, transcript deleted) wrote `MANDATE_BOUND` as its own text block with a Bash call in the same response: the marker was found while the tool call was still running and the turn went on without a message. (4) **The real restart** (SCI checkpoint M, same day): predecessor released 07:41:48.9Z, successor bound 07:41:57.1Z, first tool call 07:41:58.0Z (0.9 s after the bind; 14 tool calls later `handoff` still read RUNNING); no "proceed" message was sent; the predecessor was idle and was then stopped.

**Routing by actor id stays explicit.** `mandate_watch.route` still answers AMBIGUOUS when more than one live session answers to a name and none is the marker-host; no caller picks silently: `strategic_advisor.py` refuses a SENT record whose receipt names an ambiguous or different session and lists AMBIGUOUS candidates in the recipients view. What was wrong was a human reading a ListAgents row by position; the README now says to re-run ListAgents after the launch and take the row by name and start age, and `handoff` prints both.

**Limit still possible.** One probe, one model and effort, one real restart under the rule. A response that writes the bind line inside a send is still not persisted as text (earlier trial). The launcher must still run `handoff --wait` and act on STALLED: that part is procedural. The runtime has no way to deliver a message to a specific idle session except by a row the sender picks. **Recovery.** Delete the `handoff` subcommand and its three helper functions; the README row keeps the older recipe (message after BOUND).

**Proof run.** 4 tests (verbatim at file and line; the question picks the quantity with its caveats; whole-word names, a prefix is not the name; origin groups and the repeated-value flag).
