### How the hash is defined, and what it deliberately excludes

Per `plan_defined_parameters.md` § P5:

```
CANDIDATE_CONTENT_HASH = SHA-256( "legend-candidate-v1\n" + <tree-oid> + "\n" + <base-head-oid> )
```

Reproduce it with:

```bash
printf 'legend-candidate-v1\n%s\n%s' \
  "$(git rev-parse 04cbd3bd^{tree})" "$(git rev-parse 749a9a9b)" | shasum -a 256
```

**The hash covers the tree at `04cbd3bd`, which does not include this manifest.** A manifest
cannot contain a hash of a tree that contains the manifest — that is a fixed point, not an
oversight. The hash therefore binds *the content proposed for integration*, and this file is the
declaration about that content, in the same relation a signature has to what it signs. Any
material change to the proposed content invalidates it and every approval bound to it (GATE 5).
