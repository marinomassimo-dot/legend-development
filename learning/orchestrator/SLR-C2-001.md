## PROBLEMS ENCOUNTERED

**The problem was my own classification, and it came before the measurement.**

Building the runtime inventory I saw two Scientist worktrees each reporting one modified file, at
the same path, and wrote:

> *"Two writers on one file is the shape §14 exists to prevent, applied to content rather than to
> a directory."*

That sentence was produced from **co-occurrence** — two dirty entries, one path — and from nothing
else. I had not diffed the blobs. I then carried the classification forward into a recommendation
that it be resolved before registration, which was correct advice reached by an argument that did
not hold.

One command would have settled it at the moment of flagging:

```bash
git hash-object <worktree-a>/<path>   # 86bba8bb…
git hash-object <worktree-b>/<path>   # 86bba8bb…  ← identical
```

## CORE FINDING

> **The observed risk is not evidence loss and not interpretive conflict. It is the same
> non-canonical working state present in several working directories, committable against a
> canonical history that has already moved past it.**

Nothing was unintegrated. Nothing was divergent. Three copies of one superseded delta sat in three
working states, and the danger ran in the opposite direction to the one flagged: **committing**
the stale edit and merging it would conflict on those two lines, and a resolution favouring the
branch would regress the canonical manifest — restoring `-05`, dropping `-06`, the six figure
artifacts and the four locators. A silent scientific regression wearing the costume of a routine
merge conflict.

## LEARNING

**A conflict class must be established from content, never from co-occurrence.** Two actors
touching one path is an *observation*. Whether it is a conflict, a duplication, or a
already-canonical no-op is a *measurement*, and the measurement is one command. Naming the class
first attaches a severity — and a governance clause, here §14 — to something that has not been
shown to belong to it. That misdirects the remedy: I recommended resolving an ownership dispute
that did not exist, while the actual hazard (a future `WORK_COMMIT` regressing the canon) went
unnamed until the measurement.

The asymmetry that makes this worth recording: over-classification is not the safe direction. It
*feels* conservative, because the stronger claim implies more caution. But it points the fix at
the wrong object, and in a system that accumulates, a remedy aimed at the wrong object is filed as
though the real one had been handled.
