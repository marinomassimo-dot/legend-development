# PROTOCOL — FILE_GENERATION_RULE

## STATUS
This protocol is:

- MANDATORY
- NON-INTERPRETABLE
- NON-REDUCIBLE
- NON-BYPASSABLE

Every file generation must adhere to these rules in full.

Violation = INVALID OUTPUT

---

## 0. PROTOCOL ACTIVATION

This protocol is activated with the command:

> Run protocol: file_generation_rule

When active:
→ all rules become binding

---

## 0.1 REQUIRED OUTPUT FORMAT (CRITICAL)

The required output is NOT:

- text in chat
- copy-paste
- markdown blocks to be copied manually

The required output is:

> A REAL, SAVEABLE FILE (.md)

It must therefore be provided:

- as a file
- with the exact requested name
- ready to be saved to the operator's device
- immediately usable as a source

---

## 1. MANDATORY COMPLETENESS

Every file must be:

- complete
- definitive
- self-consistent
- immediately usable

The following are NOT allowed:

- placeholders
- missing parts
- empty sections
- references to external content that is not included
- any need for manual editing

---

## 2. NO PARTIAL OUTPUT

It is EXPRESSLY FORBIDDEN to:

- create incomplete files
- create placeholder files
- create files with structure only
- create files "to be completed later"

A partial file is defined as:

> INVALID OUTPUT

---

## 3. HANDLING LONG FILES (CRITICAL RULE)

If the file is too long or there is a risk of:

- truncation
- content loss
- formatting error
- incomplete output

THEN:

→ do NOT generate the file

→ respond EXACTLY with:

> FILE NOT GENERATED — RISK OF INCOMPLETE OUTPUT

→ and provide:

- the complete content in chat (if possible)
  or
- clear instructions for manual creation

---

## 4. NO AUTOMATIC REDUCTION

It is NOT allowed to:

- shorten the content
- simplify to "make it fit"
- cut sections
- omit relevant parts

If the file cannot be generated correctly:

→ it must NOT be generated

---

## 5. OPERATIONAL CONSISTENCY

Every file must:

- have correct naming
- be consistent with the request
- respect the complete structure
- be ready for direct use as a source

---

## 6. PRE-OUTPUT VERIFICATION (MANDATORY)

Before generation you must verify:

- Is the content complete? → YES
- Is everything included? → YES
- Is manual editing required? → NO

If even a single answer is non-compliant:

→ DO NOT GENERATE THE FILE

---

## 7. OPERATING PRINCIPLE

Better:

> no file

than:

> an incomplete or misleading file

---

## 8. PURPOSE

This protocol exists to:

- eliminate operational errors
- avoid proliferation of versions
- guarantee file quality and reliability
- keep the system usable even from mobile

---

## 9. OUTPUT STANDARD

Every file request must be interpreted as:

> "Generate a saveable .md file (not copy-paste)"

If this standard is not respected:
→ INVALID OUTPUT
